## Resumen

El `dataset.yaml` final que YOLOv8 consume para entrenar (`yolo train data=dataset.yaml ...`) se **genera automáticamente** al final del split (EN-003). No es un archivo editado a mano. Esto evita drift entre el orden de clases del código (`CLASS_NAMES` en `split_dataset.py`) y la config que ve YOLO.

## Estructura del `dataset.yaml` generado

```yaml

  4: otras_lesiones
```

## Decisiones de diseño

### `path` absoluto

El `path` se resuelve a la ruta absoluta del entorno donde corre el split (`output.resolve()` en Python). Esto significa que el `dataset.yaml` generado **no es portátil** entre máquinas — pero sí es **inequívoco**: YOLOv8 no se confunde por dónde está la cwd al lanzar el training.

Cuando otro miembro del equipo clone el repo y ejecute `split_dataset.py`, regenerará el `dataset.yaml` con SU ruta absoluta. El template versionado en el repo es solo para referencia humana.

### `nc` y `names` desde `CLASS_NAMES`

`CLASS_NAMES` está definida UNA sola vez en `scripts/split_dataset.py`:

```python
CLASS_NAMES = [
    "sano",
    "antracnosis",
    "oidio",
    "pudricion_peduncular",
    "otras_lesiones",
]
```

El YAML se genera iterando esa lista. Si en el futuro se añade/elimina una clase, basta con editar `CLASS_NAMES` y re-ejecutar el split — el YAML se actualiza solo, y el orden YOLO también.

### `test` incluido (no es estándar YOLOv8)

YOLOv8 acepta opcionalmente `test:` además de `train` y `val`. Nuestro pipeline lo usa para la **evaluación final** en Sprint 3 (RN-001 — mAP@0.5 ≥ 0.85 sobre test set). Los modelos entrenados con `yolo train` no tocan el `test` directamente; la evaluación se hace con `yolo val data=dataset.yaml split=test`.

## Validación del template

El archivo versionado [`data/processed/dataset.yaml.template`](../../../../data/processed/dataset.yaml.template) sirve como **contrato versionado** del schema. Lo verificamos parseable:

```python
import yaml
with open("data/processed/dataset.yaml.template") as f:
    config = yaml.safe_load(f)

assert config["nc"] == 5
assert config["names"] == {
    0: "sano",
    1: "antracnosis",
    2: "oidio",
    3: "pudricion_peduncular",
    4: "otras_lesiones",
}
assert "train" in config and "val" in config and "test" in config
print("OK schema valido")
```

## Notas técnicas

- **YAML safe-load:** el archivo es YAML estándar 1.2, parseable por PyYAML, ruamel.yaml o el parser de Ultralytics sin problemas.
- **Encoding UTF-8:** los nombres de clase pueden contener acentos en versiones futuras (si añadimos descripciones), pero los slugs (`sano`, `antracnosis`, ...) son ASCII puro por diseño.
- **Path en Windows:** se usa `pathlib.Path.as_posix()` para producir paths con `/` en lugar de `\`. YOLOv8 acepta ambos, pero `/` es más portable.
