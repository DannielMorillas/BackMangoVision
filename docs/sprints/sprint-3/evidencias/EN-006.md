## Fase intermedia — Baseline público de enfermedades (`disease-v1`)

El modelo final (datos Casma, 5 clases) sigue **bloqueado** por la anotación en CVAT de las fotos de Casma (HU-010) y por la visita de fructificación. Para **de-riesgar** EN-006 sin esperar ese dataset, se entrena primero un detector de enfermedades sobre un dataset **público** en formato YOLOv8:

- **Dataset:** Mango Leaf detection (PenPixel, Roboflow), 8 clases, 2286 imágenes. Incluye `Anthracnose` (antracnosis) y `Powdery-Mildew` (oídio), dos de las clases del catálogo. Verificación completa e íntegra en [`screenshots/disease-v1/DATASET.md`](screenshots/disease-v1/DATASET.md).
- **Limitación:** es dataset de **hoja**, no de fruto Kent → NO reemplaza al dataset propio; sirve para validar el pipeline y el experimento de transfer learning.

### Experimento O1 vs O2 (transfer learning)

Mismo dataset y mismos hiperparámetros, dos pesos iniciales, se comparan por `mAP@0.5`:

| Opción | Pesos iniciales | `--tag` | Hipótesis |
|---|---|---|---|
| **O1** (desde cero) | `yolov8n.pt` | `disease-v1` | Línea base sin pre-entrenamiento. |
| **O2** (transfer) | `ml/models/baseline-v0.pt` (EN-005) | `disease-v2-transfer` | El backbone ya sabe localizar mangos → mejor/más rápido `mAP`. |

```powershell
# O1 — desde cero
python scripts/train_yolo.py --tag disease-v1 `
    --data data/raw/public/mango-leaf-disease-yolov8/data.yaml --epochs 60 --device 0

# O2 — transfer desde el baseline de fruto (EN-005)
python scripts/train_yolo.py --tag disease-v2-transfer `
    --data data/raw/public/mango-leaf-disease-yolov8/data.yaml --epochs 60 `
    --resume-from ml/models/baseline-v0.pt --device 0
```

## Plan B si mAP < 0.85 en RN-001

Si el modelo no alcanza el umbral de RN-001 en el test set, iterar:

1. **Reentrenar con más épocas** (150-200).
2. **Subir a modelo más grande**: `yolov8s.pt` (small) o `yolov8m.pt` (medium).
3. **Ajustar hiperparámetros** (lr0, lrf, mosaic prob, mixup prob).
4. **Augmentar más datos** mediante capturas adicionales en Casma o anotando más del dataset clasificación.
5. **Class-balancing**: si una clase domina el error, sobre-samplear las minoritarias.

Cada iteración se commitea como `custom-v2`, `custom-v3`, etc.

## Notas técnicas

- **Resumir desde baseline-v0** no es lo mismo que entrenar de cero: YOLOv8 detecta que el número de clases cambió (de 2 a 5) y ajusta la última capa automáticamente. El backbone se mantiene con los pesos aprendidos.
- **Tiempo estimado en GPU T4:** ~2-3 horas para 100 epochs con dataset de 370 imágenes.
- **Tiempo en CPU:** prohibitivo (~50-100 horas). No intentar.
