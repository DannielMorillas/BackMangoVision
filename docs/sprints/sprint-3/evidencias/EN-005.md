## Resumen

Primer entrenamiento del Sprint 3. Usa el dataset público `mango-v1-yolov8` (Roboflow) para producir un modelo de detección de **frutos** de mango (no de enfermedades, porque las clases del Roboflow son `ripe`/`un_ripe`). Los pesos resultantes (`ml/models/baseline-v0.pt`) sirven como **punto de inicio** del modelo de EN-006 — la red ya sabe localizar mangos, EN-006 le enseñará a clasificar lesiones sobre los frutos detectados.

Esto materializa la **Opción E** aprobada en EN-001.

## Hiperparámetros propuestos

| Parámetro | Valor | Justificación |
|---|---|---|
| `model` | `yolov8n.pt` (nano) | Modelo más pequeño de la familia. Suficiente para localización + rápido de entrenar. Para EN-006 podemos escalar a `yolov8s.pt` si CPU/GPU lo aguantan. |
| `epochs` | 50 | Suficiente para que la red aprenda a localizar frutos con 1500+ imágenes de train. |
| `imgsz` | 640 | Default YOLOv8; balance entre precisión y velocidad. |
| `batch` | 16 | Asumiendo GPU con ≥ 8 GB VRAM. Reducir a 8 si OOM. |
| `lr` | default | YOLOv8 maneja learning rate scheduling internamente (warmup + cosine decay). |
| `augment` | default | Mosaic, mixup, hsv, flips, etc. — viene activado por defecto. |

## Notas técnicas

- **Por qué pre-training con `ripe`/`un_ripe`:** la red aprende la **forma del fruto** y dónde mirar. Cuando EN-006 reemplaza la cabeza de clasificación por nuestras 5 clases de enfermedades, el backbone (extractor de features) ya está optimizado para mangos.
- **Transfer learning en EN-006:** se hace con `--resume-from ml/models/baseline-v0.pt`. YOLO automáticamente ajusta la cabeza de clases.
- **Si la GPU local no aguanta:** subir el dataset a Google Drive, montar en Colab y entrenar ahí. El notebook auxiliar [`ml/notebooks/colab_train.ipynb`](../../../../ml/notebooks/colab_train.ipynb) automatiza todo el flujo (GPU check → install → mount Drive → unzip → genera data.yaml con rutas absolutas → train → val mAP → copia resultados a Drive).
