## Resumen

El servicio de inferencia mide el tiempo de cada predicción con `time.perf_counter()` y lo expone como `inference_time_ms`. La ruta `/api/predict` persiste ese valor en cada fila de `predictions` (columna `inference_time_ms`, ya existente en el modelo `Prediction`).

## Flujo

1. `InferenceService.predict()` cronometra la inferencia → `InferenceResult.inference_time_ms`.
2. `predict.py` guarda ese ms en **cada** `Prediction` de la imagen.
3. Se consume en:
   - `/api/metricas` → `avg_inference_time_ms` y `p95_inference_time_ms` (EN-014).
   - `/api/diagnosticos/resumen` → `avg_inference_time_ms` (dashboard).
   - `DiagnosticResultPage` → muestra el tiempo del diagnóstico.

## Relación con RN-002

RN-002 exige diagnóstico ≤ 5 s **end-to-end**. Este registro da la base para medirlo. El benchmark real end-to-end (upload + inferencia + render) se hará con la app levantada y el modelo real.

## Criterios de aceptación

- [x] `inference_time_ms` se calcula por predicción.
- [x] Se persiste en `predictions`.
- [x] Se agrega (avg/p95) en métricas y resumen.
