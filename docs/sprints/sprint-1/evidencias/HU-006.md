> **Como** ingeniero agrónomo, **quiero** recuperar mi contraseña si la olvidé, **para** volver a acceder al sistema sin depender del administrador.

## Resumen

Flujo de dos pasos:

1. `POST /api/auth/forgot-password { email }` → genera un token aleatorio de 32 bytes, persiste su **hash SHA-256** en `password_reset_tokens` con expiración de 2 horas. **Siempre** devuelve 200 con mensaje genérico (no filtra qué emails existen). En modo `development`, la respuesta incluye `debug_token` para poder probar el flujo sin SMTP.
2. `POST /api/auth/reset-password { token, new_password }` → busca el hash, valida que no esté usado ni expirado, actualiza la contraseña (bcrypt), marca el token como usado.

## Cómo probar (manual)

```powershell
# 1. Solicitar reset:
curl -X POST http://localhost:8000/api/auth/forgot-password `
  -H "Content-Type: application/json" `
  -d '{"email":"admin@example.com"}'
# Respuesta (DEV): { "message": "Si el correo existe...", "debug_token": "xyz...", "debug_expires_at": "..." }

# 2. Aplicar reset con el token:
curl -X POST http://localhost:8000/api/auth/reset-password `
  -H "Content-Type: application/json" `
  -d '{"token":"xyz...","new_password":"NuevaClave456"}'
# Respuesta: 204 No Content

# 3. Login con la nueva contraseña:
curl -X POST http://localhost:8000/api/auth/login `
  -H "Content-Type: application/json" `
  -d '{"email":"admin@example.com","password":"NuevaClave456"}'
```

## Criterios verificados

- [x] El endpoint solicita el correo registrado.
- [x] Si existe, se genera un token de restablecimiento válido por 2 h.
- [x] El endpoint de reset permite cambiar la contraseña con validación de fortaleza (`min_length=8`).
- [x] Si el correo no existe, mensaje genérico (sin filtrar usuarios).
- [x] El token solo se puede usar una vez (`used_at` se setea en el primer uso).
- [x] Tokens expirados se rechazan.

## Notas técnicas

- **Solo persistimos el hash del token, no el token plano.** Si la BD se filtra, un atacante no puede usar los tokens. Esto es el mismo patrón que para passwords.
- En `production` el `debug_token` será `None` siempre. La integración SMTP real se hará en Sprint 5 con configuración del servidor de ARA Export (decisión del usuario).
- El TTL de 2 horas viene del plan; configurable vía `JWT_RESET_EXPIRES_HOURS`.
- Si un usuario solicita varios resets, los tokens previos siguen activos hasta que expiran o se usan. En el futuro podría invalidarse el viejo al emitir uno nuevo, pero no es crítico para Sprint 1.
