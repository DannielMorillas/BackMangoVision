> **Como** administrador del sistema, **quiero** crear cuentas de usuario para los ingenieros agrónomos de ARA Export, **para** que puedan acceder al sistema con sus propias credenciales.

## Resumen

`POST /api/admin/users` — protegido por `require_admin`. Acepta email, nombre, apellido, rol y contraseña temporal. El usuario creado tiene `must_change_password=true` para forzar el cambio en el primer login (la UI lo manejará).

## Archivos clave

- [backend/app/api/routes/admin.py](../../../../backend/app/api/routes/admin.py) — endpoint `POST /api/admin/users`.
- [backend/app/api/deps.py](../../../../backend/app/api/deps.py) — `require_admin` (depende de `get_current_user`).
- [backend/app/schemas/user.py](../../../../backend/app/schemas/user.py) — `UserCreate` DTO.

## Cómo probar (manual)

```powershell
# Necesitas estar logueado como admin (ver seed inicial en docs cuando exista).
$ADMIN_TOKEN = "eyJ..."

curl -X POST http://localhost:8000/api/admin/users `
  -H "Authorization: Bearer $ADMIN_TOKEN" `
  -H "Content-Type: application/json" `
  -d '{
    "email":"agronomo.nuevo@example.com",
    "first_name":"Maria","last_name":"Gomez",
    "role":"agronomist","temp_password":"Temporal123"
  }'
# Respuesta: 201 con datos del usuario, must_change_password=true
```

## Frontend asociado

- [frontend/src/pages/AdminUsersPage.tsx](../../../../frontend/src/pages/AdminUsersPage.tsx) — pantalla en `/admin/usuarios` con tabla de usuarios, formulario para crear y botón de activar/desactivar (HU-008).
- [frontend/src/services/admin.ts](../../../../frontend/src/services/admin.ts) — cliente del API admin.
- La ruta se protege con `<ProtectedRoute requireRole="admin">` (un agronomista que la abra es redirigido a `/dashboard`).
- Seed inicial: [backend/scripts/seed_initial_admin.py](../../../../backend/scripts/seed_initial_admin.py) crea el primer admin para que exista alguien con permiso de invocar este endpoint.

## Tests automatizados backend (3 Pytest verdes)

| Test | Verifica |
|---|---|
| `test_create_user_requires_admin` | Un agronomist intentando crear usuarios → 403 |
| `test_admin_creates_user_must_change_password` | Admin crea agronomista → 201 + el nuevo usuario puede loguearse con la contraseña temporal |
| `test_admin_cannot_duplicate_email` | Email ya existente → 409 |

## Criterios verificados

- [x] Solo el administrador puede crear usuarios (`require_admin` lanza 403 si rol ≠ admin).
- [x] El formulario solicita: nombre, apellido, correo, rol y contraseña temporal (Pydantic `UserCreate`).
- [x] El usuario creado puede iniciar sesión con la contraseña temporal.
- [x] Flag `must_change_password` = true en el nuevo usuario.
- [x] Email único: 409 si se duplica.
- [x] Contraseña almacenada con bcrypt.

## Notas técnicas

- El flujo "cambio obligatorio en primer login" requiere lógica frontend (HU-007-FE pendiente): cuando `must_change_password=true` en el `/me`, la app redirige a una pantalla `/cambiar-clave` antes de cualquier otra ruta.
- Falta un seed para crear el **primer admin** en BD. Esto se documentará al cierre del sprint cuando construyamos el script `db/seeds/initial_admin.py`.
