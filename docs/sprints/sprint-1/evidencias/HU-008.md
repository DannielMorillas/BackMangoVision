> **Como** administrador, **quiero** desactivar o reactivar cuentas de ingenieros que ya no trabajan en ARA Export, **para** controlar el acceso sin eliminar el historial de diagnósticos.

## Resumen

`PATCH /api/admin/users/{id}/status` — protegido por `require_admin`. Cambia el flag `is_active` del usuario. Un admin **no puede desactivarse a sí mismo** (regla de negocio para evitar bloquear el sistema). El historial (futuros `predictions`, `manual_labels`) se conserva porque las FKs son `ON DELETE RESTRICT`.

## Archivos clave

- [backend/app/api/routes/admin.py](../../../../backend/app/api/routes/admin.py) — endpoint `PATCH /api/admin/users/{id}/status`.
- [backend/app/schemas/user.py](../../../../backend/app/schemas/user.py) — `UserStatusUpdate`.
- [backend/app/api/routes/auth.py](../../../../backend/app/api/routes/auth.py) — `login` valida `is_active`.

## Cómo probar (manual)

```powershell
$ADMIN_TOKEN = "eyJ..."

# Desactivar:
curl -X PATCH http://localhost:8000/api/admin/users/2/status `
  -H "Authorization: Bearer $ADMIN_TOKEN" `
  -H "Content-Type: application/json" `
  -d '{"is_active":false}'

# Intentar loguearse con la cuenta desactivada → 403

# Reactivar:
curl -X PATCH http://localhost:8000/api/admin/users/2/status `
  -H "Authorization: Bearer $ADMIN_TOKEN" `
  -d '{"is_active":true}'
```

## Criterios verificados

- [x] El administrador puede cambiar el estado de una cuenta.
- [x] Un usuario inactivo no puede iniciar sesión (login responde 403, no 401, para que el frontend pueda mostrar mensaje específico).
- [x] El historial de diagnósticos se conserva (no se borra el row de `users`).
- [x] Regla extra de seguridad: el admin no puede desactivarse a sí mismo.

## Notas técnicas

- El endpoint también podría agregar lógica para *invalidar tokens activos* del usuario cuando se desactiva. Por simplicidad (JWT stateless), un token emitido **antes** de desactivar sigue siendo válido hasta su `exp`. La defensa real está en `get_current_user`: hace `db.get(User, sub)` y rechaza si `is_active=false`. Es decir, **cualquier request del usuario desactivado falla con 401 incluso si el token aún no expiró**.
- Cuando se implemente HU-019 (gestionar modelos IA), se podrá listar usuarios con `GET /api/admin/users` (ya implementado).
